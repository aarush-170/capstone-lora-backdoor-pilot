This decides whether we **reproduce** a detector (run the authors' code) or **reimplement** it from the paper, and it feeds the feasibility section of the Phase 1 report. Method: GitHub and Hugging Face APIs, the arXiv pages, and the public WSD repository's files. ## What the WSD code tells us (resolves part of open question Q-008)
- Detector: `StandardScaler` then `LogisticRegression(C=C, max_iter=1000, class_weight="balanced")`; threshold on validation scores (gap-based if separable, otherwise Youden's J). The value of `C` was not read.
- Setting: single layer index 20 (layer 21), the four projections q/k/v/o, rank 16, LoRA alpha 32, learning rates 1e-4, 2e-4, 3e-4, triggers `cf` and `Important update:`, poisoning 1%, 3%, 5%.
- Features per projection (training path, `core/geometric_base.py`): sigma_1; Frobenius norm; **energy = sigma_1^2 / sum of sigma^2**; **entropy on sigma / sum of sigma** (not squared); **kurtosis of the flattened update entries** (scipy default, i.e. excess kurtosis). The scan path (`core/detector.py`) builds the update from the LoRA factors via QR and an r x r SVD like ours and does **not** apply the alpha/r scaling.
- The repo has two code paths for the statistics; I read the first and only the start of the second, so the exact entropy and kurtosis in the scan path are unchecked.
- Compared with ours (`common/features.py`, `detector_standin.py`): ours scales by alpha/r (a constant factor of 2; it does not matter after z-scoring if all adapters share alpha and rank), uses an entropy on the squared singular-value shares, kurtosis of the singular values, and the mean over all layers instead of layer 21. The paper text I read earlier said energy = sigma_1 / sum of sigma; the code says sigma_1^2 / sum of sigma^2. Treat the code as the working definition and note the discrepancy.

## Decision and next steps
See DEC-012. In short: reimplement WSD and Z-PEFT from their papers (WSD cross-checked against its public repo); run PEFTGuard's code on selected PADBench folders for our own analysis; ask the authors (PEFTGuard, WSD) about licences and PADBench labelling; never redistribute their code or data.
